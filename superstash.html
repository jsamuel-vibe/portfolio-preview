Superstash: a personal knowledge library for designers

I designed and built a place to collect references and notes, with a longer-term goal: giving AI tools useful context from what I save, learn and think.

Long story short

My references and thoughts were scattered across different apps. I kept collecting things to learn from, but often struggled to bring that knowledge back into the work I was doing.

I wanted Superstash to connect that collection with AI tools, helping resurface forgotten references and inform new ideas. Working solo, I started with the foundation: browser capture, a shared library for saves and notes, and AI-generated descriptions and tags.

Using it myself made quick note-taking a priority. I chose a simpler interface that I could build sooner, with a note field directly in the gallery and compact navigation.

The API connection remains planned. My immediate focus is fixing bugs and refining the existing UI and workflows before expanding the AI capabilities.

The problem

When something online caught my eye, I had no single place to keep it. Things ended up spread across Pinterest, screenshots, Notion, my downloads folder and chat apps.

Saving wasn’t the hard part. Finding things again was. I kept forgetting where I’d put them, so I kept relearning things I already knew.

Why other tools didn’t work for me

NotionToo many steps to save one thing
mymindGreat app, but too expensive for me

So I decided to build my own: quick to save, easy to find.

Limits

#1

Just me, after work. I couldn’t build and polish everything.

#2

Working beats pretty. I chose rough but working over polished but slow.

#3

Built to grow. I made choices I wouldn’t have to undo when adding features later.

What I decided

01 I made saving one click. It backfired.

My first idea was to remove every step. A Save button appeared on any image I hovered over, so saving took one click.

It worked too well. I saved everything, and my library became the same messy pile I was trying to escape. Easy saving didn’t make my saves useful.

02 I didn’t fix it right away

I knew the fix: make saving a little harder on purpose. But saving and finding things had to work first, so I put the fix on hold. Choosing what to leave for later was a decision too.

03 Saving now takes two clicks (in progress)

Instead of a button on every image, you right-click and choose Save to Superstash. It’s one extra step, so saving becomes a choice instead of a habit.

The catch: right-click is harder to discover, and phones don’t have it. This hasn’t shipped yet, and I’m still testing it.

04 AI does the sorting

To make things easy to find, AI adds tags and a short description to every save. I wrote the prompts so it describes each save the way a person would. Nobody has to organise anything by hand. This part works best so far.

A smaller first release, built around quick capture

Quick note-taking became a priority through using Superstash myself. I brought a note field directly into the gallery, keeping it immediately available without letting it dominate the collection.

I chose a compact icon rail instead of an expanded sidebar, and kept the product centred on the main workspace and settings. This was a simpler version to build, with fewer screens to design and maintain.

I preferred the visual polish of some earlier explorations. For this release, I chose to get a useful version working sooner and leave further refinement for later.

What I learned

This was my first UX project, and I’m still its only user, so there are no numbers yet. What I do have is three mistakes that changed how I work.

  1. #1

    I made saving too easy

    I removed every step, so I saved everything, and my library became the messy pile I was trying to escape.

    Now

    I remember that easy and good aren’t the same thing. Removing friction at the start can just move the problem further down the line. I only caught it because I used the tool every day.

  2. #2

    I started with screens

    I spent a long time on the UI and kept coming up with new ideas, without deciding what the product needed to do. I often didn’t know what to work on next.

    Now

    I set the goal and the main flow before touching any UI.

  3. #3

    I designed an app, not a solution

    I wanted to build an app, so I kept adding screens. The real work was the core problem: saving things and finding them again.

    Now

    I build the core first, with help from AI coding tools, and leave polish for later.
